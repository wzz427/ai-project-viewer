# SPEC-022-关机弹窗(重启时冒出的 git.exe 错误框关不掉)

> 状态:Draft —— 真值在 specs/INDEX.md 那一行
> 创建:2026-11-18;Pre-Draft 讨论 = owner 报障(带手机照片)+另一 AI 初判,本 SPEC §一为复核结论

## 〇、值不值得做(两栏三出口)

- 好处:owner 每次重启,只要 ProjectViewer 开着且激活项目有文件动静,就**有概率弹 `git.exe - Application Error (0xc0000142)` 错误框卡住重启**(2026-11-18 17:11 实发一次,"14 个应用关机屏"被它骑脸);修掉=本项目从此不可能以任何子进程拖住关机。受影响=owner 本人,触发即 100% 卡关机。
- 代价:git.rs 一个 Windows 分支函数+spawn() 一行闸+3 个 cargo 测试,半天内。可能碰坏什么:关机瞬间最后一批 git 刷新被跳过——无感(§20 git 快照零持久化,下次启动全量重读)。
- 判:**值→做**(用户能感觉到的 bug 不上秤,一律修);按 2026-10-31 规,方案落纸面停下等 owner 确认。

## 一、Pre-Draft 结论(证据复核)

**事件还原(坐实的部分):**
- 照片:关机屏"正在关闭 14 个应用"上叠 `git.exe - Application Error 0xc0000142` 框;水印 2026-11-18 17:12。
- System 日志 Event 1074:**17:11:40 发起重启**(时间线吻合:发起→关机屏→17:12 拍照)。
- 0xc0000142 = 进程在"会话正在结束"的窗口里被拉起、加载器初始化失败的**确定性症状**——不是 git 坏了,是"关机途中有人启动了 git.exe"。该错误框由系统加载器弹出,`CREATE_NO_WINDOW` 拦不住(我们 git.rs:45-51 早有此旗,与本弹窗无关)。

**本项目的自动链(代码坐实,是全机唯一查到的"文件变化→自动拉 git"后台路径):**
`watcher.rs`(400ms 防抖,盯激活项目根)→ `fs-changed` → `watcherStore.svelte.ts:138` **每批直调** `refreshGitNow`(注释明说不做防抖)→ `git_snapshot` 命令 → `git.rs:584 git status --porcelain=v2` → `git.rs:64 spawn()`。
关机场景成立的条件:激活项目(MyProxy,`state.json` 内容证实)目录里有别的程序在关机时写文件——照片里 `MyProxy · 0.7.84` 本身就在被关闭名单里,它在退出时刷日志/状态文件是大概率事件。**代码里没有任何关机/会话结束闸**(`rg -i 'endsession|shuttingdown|shutdown|logoff'` src-tauri 全空)。

**归因三嫌疑(诚实版):**
| 嫌疑 | 判 | 依据 |
|---|---|---|
| ProjectViewer | **可能,未实锤** | 自动链代码坐实+MyProxy 正被关闭会制造文件动静;但"当时在运行"无正面证据(应用数据目录 11-18 零写入,state.json mtime 10-31)——开机在跑但全天零状态变化时数据目录可以零写入,故不能排除也不能坐实 |
| ZCode | 可能 | 在关机名单上,常驻且频繁拉 git;关机瞬间若有后台 shell/git 轮询在飞,同样弹此框 |
| MyProxy 应用 | 基本排除 | 源码里 git 调用全在 `tools/`、`tests/`(手动/CI 开发工具),运行中的代理应用退出不拉 git |

另一 AI 的「17:11:38 保存的当前项目就是 MyProxy」:**未能在任何文件上复核到**(state.json mtime=10-31,应用数据目录今日零写入),不作依据;时间上倒与 1074(17:11:40)贴近,可能看的就是系统事件。

**结论**:归因可以不闭环——"本项目在关机窗口自动拉子进程"是**确定性缺陷**,0xc0000142 是其必然症状,无论本次弹窗是谁家的都修;修完后若复发,即证明是 ZCode 等他方,排除法自然闭环。

- 核心选择题(呈 owner):修法 A(推荐)= git 唯一出口 `spawn()` 一处闸;B = 不修记账观察。推荐 A,理由见 §四。
- 标杆对照:本应用其余拉子进程处(run.rs 脚本/handoff 移交/updater)全是**用户动作触发**,关机场景不会自己发生;唯一"无人在场也自动拉"的就是 git 刷新——闸打在它唯一出口上,是结构性收口不是补丁(判据:换任何项目,「后台自动 spawn 必须过会话结束闸」照样成立)。
- **界面确认**:N/A(零界面变化)。

| R# | 需求(使用者视角) |

## 四、技术实现方案(确认后才开发)

- 动 `src-tauri/src/git.rs` 一处:`spawn()` 之前加会话闸;新增 `session_ending()`(Windows-only)。
- 关键取舍:零新依赖——不引 `windows` crate,直接 `extern "system" { fn GetSystemMetrics(nIndex: i32) -> i32; }`,`SM_SHUTTINGDOWN = 0x2000`(非零=会话正在关)。edition 2021,普通 extern 块即可。调用成本≈一次用户态查询,相对 spawn 一个进程可忽略。

### 决策依据(后续翻案只翻这节)

| 结论 | 理由 | 当时排除了什么 | 为什么排除 |
|---|---|---|---|
| D1 闸打在 `git.rs spawn()` 单点 | 全部 git 调用(status/diff/log)都过 `run_git`/`run_git_capped`→`spawn()`(模块头注释明示"one spawn path");关掉一处=关掉全部 | 闸打在前端(不发 invoke) | 前端在关机时还剩多少生命期不可控;Rust 侧是最后一道、也是必经的一道 |
| D2 用 `GetSystemMetrics(SM_SHUTTINGDOWN)` | 关机/注销进行中该值非零,恰是 0xc0000142 的成因窗口;调用便宜、无权限要求、零依赖 | ①WM_ENDSESSION 钩子(tao 层没有现成事件,要动窗口过程) ②应用退出时停 watcher | ①为这一个场景动窗口过程属大炮打蚊子 ②停 watcher 管不住"关机已开始、webview 还在跑"的窗口期,闸必须贴着 spawn 才封得住 |
| D3 跳过=返回普通 Err(非 missing) | UI 正在死,快照进 error 态随进程消亡;绝不能映射 missing(下次启动 §20 全量重读,无脏状态可留) | 静默返回假快照 | 造假数据违反"零持久化=零污染"的 §20 契约 |
| D4 不给 run.rs/handoff/updater 加闸 | 三处全是用户动作触发(点按钮),关机途中无人点;自动路径仅 git 一条 | 全出口统一加闸 | 三处各加=为不存在的场景付三倍测试面;真出现"用户在关机屏上还点按钮"的场景时系统本身会拦 |

**同一条依据已同步写进它管的那段代码的头注释**(依据和它管的东西不许分家)——施工时落实。
