# SPEC-015-项目页签拖拽换位:顶栏的项目标签可以互相拖动排序吗?

> 创建:2026-10-12。Pre-Draft:owner 原话"项目页签之间不能进行移动,要求项目页签也可以互相移动位置。
> 吸取之前做文件页签移动的教训"——交互模型**整体复用**文件页签打磨成熟的方案(lessons L10 全家),
> 不另起炉灶。A2 对齐=本句(owner 已指定做什么+照什么做),免重复问答。

## 〇、值不值得做(两栏三出口,一行各一句)

- 好处:多项目用户(owner 现常态 2+ 个)自己调顺序,高频小操作;复用文件页签方案,增量成本低。
- 代价:ProjectTabs 加拖拽处理器+projectStore 两个纯重排函数;可能碰坏=右键菜单/激活点击与拖拽的事件竞争(既有方案已解),持久化顺序(现成通道,零新增)。
- 判:值→做(增量需求,owner 明确要求)。

## 一、Pre-Draft 结论

- 核心选择题:自研新手势 vs 复用文件页签模型——owner 指令**复用**;文件页签那套经 L10 系列返修打磨(WebView2 需同时取消 dragenter+dragover、光标半区 before/after、末尾空带=扔到最右)。
- 标杆对照:与文件页签**同语言**:同样的插入线指示(前=顶线/后=底线)、同样的末尾空带语义;差异仅项目条是 40px 高、指示线画在页签盒上。
- **界面确认**:纯交互增强,无新视觉面;复用既有指示样式。N/A 线框(增量交互,模型已验收过)。

## 二、需求正文(R 编号;使用者视角)

| R# | 需求(使用者视角) |
|---|---|
| R1 | 按住任一项目页签拖到另一页签的左半/右半,松手后两者换位/插入该侧,顺序立即生效 |
| R2 | 拖到所有项目页签右侧的空带(含 + 按钮一带)松手=移到末尾 |
| R3 | 拖拽过程中有插入位置指示(目标页签顶边线=插它前面/底边线=插它后面;空带=右侧竖线) |
| R4 | 重排后关软件重开,项目顺序保持新顺序(持久化走既有通道,零新增定时器) |
| R5 | 原有能力零变化:点击激活、右键菜单、+ 加项目、首字徽标颜色跟随项目不随位置变 |

**反例规则(不许做什么)**:不许动磁盘任何东西(纯显示顺序);拖拽不许弹原生对话框/抢前台(零打扰红线);不许给 + 按钮和 Update 按钮加拖拽语义(它们不是页签);不许新增持久化字段(顺序=数组序,既有)。

## 四、技术实现方案

- 模块:`projectStore.svelte.ts` 加 `reorderProjects(fromId,toId,pos)`+`moveProjectToEnd(fromId)`(splice 模型照抄 tabsStore.reorderTabs,含 splice 后重找锚点);`ProjectTabs.svelte` 加 drag 处理器(整抄 FileTabs 结构:dragId/dropAt/bandDrop 三态)。
- 关键取舍:见决策表。

### 决策依据(后续翻案只翻这节)

| 结论 | 理由 | 当时排除了什么 | 为什么排除 |
|---|---|---|---|
| D1 | 交互模型 1:1 复用文件页签(L10 全家) | 该模型经多轮返修实证可用;两处页签同一语言,零学习成本 | 竖排菜单/上下文"Move Left/Right" | owner 指定照抄;菜单式多两步点击 |
| D2 | 持久化=数组序,零新字段 | appState 按数组序序列化 projects(既有),重排自动过防抖落盘 | 加 order 字段 | 双真值必漂(顺序字段 vs 数组序) |
| D3 | 空带含 + 按钮一带(扔右=末尾) | + 不是页签但落在条上;事件冒泡到条即空带语义,与文件页签条一致 | + 区域拒绝 drop | 末尾手势出现够不着的洞(L10 同族) |
| D4 | 拖拽期间不自动激活目标页签 | 与文件页签一致:换位≠切换;误触激活是文件页签早期教训 | hover 即切 | 高频误切换 |

**依据同步进代码头注**:D1→ProjectTabs 拖拽段注释;D2→projectStore reorderProjects 注释。
