## 背景:这次教训是什么(一段话)

ProjectViewer 项目**自带权威需求基线**(《需求文档 V1.5 FINAL》,owner 定稿入库,有增量修订纪律,兼任产品规格与 Phase 计划)。建仓时按指南总原则"答别的问题的文档已存在 → 加指针"跳过了阶段 1/2 的 spec.md/roadmap.md/specs/——这个跳法本身合理,但指南没写"基线项目怎么接入",于是 specs/ 体系整个没建。四天后 owner 要求"每段开发先写 Spec 文档",agent **没有回 00-doc-map 对号,自创了 `docs/specs/phase-N`**(位置错、命名错、无台账、无 workflow.md),被 owner 按指南原文逐条指出后返工重排。两个根因都在指南的可修补范围:**①基线项目无接入路径;②"建新结构前先对号"没有触发机制**(规矩存在 00-doc-map 里,但没有任何一行在"要建文档"那一刻把它送到眼前)。

## 建议 1(核心):00-doc-map.md 新增「特殊入场:项目已自带权威需求基线」

- **文件**:`00-doc-map.md`;**位置**:阶段 2 表格之后、阶段 3 标题之前,新增一节;并在阶段 1、阶段 2 的表后各加一行指针"(项目已自带权威需求基线时,走下方『特殊入场』,不重走正门)"。
- **草稿(可直接粘贴)**:

```markdown
## 特殊入场:项目已自带权威需求基线时的接入法

判据(同时满足才走此门):owner 已把完整需求/技术设计文档**定稿入库**(如《需求文档
Vx.x FINAL》);该文档有**变更纪律**(增量修订+变更审计,禁止整篇重写);它明确兼任
产品规格与阶段计划。此时:

- **spec.md / roadmap.md 不另建**(总原则 1:答别的问题的文档已经存在 → 加指针)——
  本表阶段 1/2 两行标注"由《基线文档》兼任",AGENTS.md 路由表指过去;
- **specs/ 台账与 docs/workflow.md 照建**,时机 = **第一个开发批次开工前**(不是第 0 天,
  也不是"痛点出现再说"——基线文档管需求与排期,不管开发状态,这一层没有替代品);
- **SPEC 的 R/V 指向基线文档的节号,不重抄正文**(两套正文必漂);粒度可与基线批次
  对齐(如 SPEC-00N ↔ 批次 N);
- 走此门的判断依据写进 handoff("为什么这么定"),别只留在对话里。
```

- **为什么**:本次返工的第一根因。指南阶段 1 假设从零讨论产出 spec.md,基线项目照字面走会造复述件(漂),照总原则走则整个 specs/ 体系被跳过(本次实况)。给正门之外的明确入口,两种极端都堵住。

## 建议 2:把"建新结构前先对号"变成到点送达的路由行

- **文件 1**:`templates/AGENTS.md` 路由表(「四、要干这件事,进哪份文档」那张表)加一行:

```markdown
| 要建任何新文档 / 目录 / 编号体系 | 🔴 先开【AI-Project-Guide/00-doc-map.md】+【templates/】对号:指南有明文的**照用**;要偏离,必须把差异+理由写进本项目对应文档(如 workflow.md 的"本项目适配"节),**不许静默自创** |
```

- **文件 2**:`00-doc-map.md` 头部引言("> **这是全书的心脏,先读这份。**"那段)末尾加一句:

```markdown
本表同时是**建新结构的对号表**:要建任何新文档/目录/编号,先回这里 + templates/ 找有没有现成的——有,照用或明记差异;没有,才允许自创。
```

- **为什么**:本次返工的第二根因。00-doc-map 里 specs/ 的位置、编号、台账、workflow.md 触发时机**全部有明文**,agent 仍然错——因为"要建 Spec 文档"那一刻,没有任何一行规则把 agent 推回 00-doc-map。指南自己的 AGENTS 模板 §一.8 说"规矩没被执行 → 往路由表加一行到点送达",本条就是按它补的。

## 建议 3:SPEC 编号/文件名格式精确到唯一写法

- **文件**:`02-dev-workflow.md` §二(specs/ 文件夹与台账)清单里加一条:

```markdown
- 文件名统一小写三位数 `spec-nnn-<短名>.md`(如 spec-002-file-system.md);台账与正文中引用可写 SPEC-002。只用一种文件名格式——本次事故里 owner 写 spec-001、指南写 SPEC-NNN、agent 写 phase-2,三种并存说明格式没有精确到"照抄都不会错"。
```

- **为什么**:格式留了自由度,三方就写出三种;规范要精确到无歧义。

## 不主张改的(本次实战验证是对的,别动)

- 三步曲(讨论→落笔→交付)、SPEC 状态机与跃迁自检门、台账"状态只住一处"、"未立项不占号/作废不删"——本次按它落位后 owner 认可,问题全部出在接入与触发,不在流程本体。
- "痛点出现才建"总原则——保留;基线项目的 specs/ 时机由建议 1 单独说清,不动总原则。
