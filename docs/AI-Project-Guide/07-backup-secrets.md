# 07 · 备份与密钥 —— 两件"晚了就救不回来"的事

> 平时价值是零,出事那天价值是全部;第一天做好花两小时,出事后再补花不回来。

---

## 一、密钥(红线,第一天立死)

**五条**:

1. **密钥永不入仓库**:密钥文件进 `.gitignore`(`.env`/`*key*`/`config.local.*` 同罪);
   提交钩子扫一道。
2. **密钥内容一个字符都不许流向输出**——print/日志/异常/命令行参数/汇报,全算。
   **"先看看里面有哪些键名"同样禁止**:安全打印一个没见过的机密文件要求预先知道它的格式,
   而你要打印恰因不知道——那个说法自我否定。
3. **程序要用就让程序自己取**(环境变量/专用 helper,中间任何一站不落地到输出)。
4. **不知道键名 → 问 owner,别自己扫。**
5. **仓库外持一份《密钥总备份》**:所有密钥/账号/恢复方法的清单(哪个密钥住哪、干什么、
   丢了怎么换)——**单独存(owner 私人存储/密码管理器),只有索引没有值**。
   建档时点 = **首个密钥引入当天**(零密钥项目第 0 天不建空账;红线本身第 0 天立)。
   它也要有自己的备份:代码在 git 里有历史,这份清单只有这一处。

**认证走公钥不走密码**:密码每次都要读出来拼进命令,被读出来就有被打印的机会
(源项目实测泄漏三次);公钥从头到尾没人需要读私钥。
损失面也不同:密码泄露=整个账号,私钥泄露=网页上删掉那条公钥就断了。

**泄了怎么办(预案先写)**:当场吊销换新 → 排查 git 历史(`git log -p | grep` 特征串),
进了历史就 rewrite 或按永久泄露处理。

## 二、备份(异地,第一天推)

- **第二个 remote 指向私有仓库**(跨平台 = 真异地);SSH 公钥认证。
- 推法:`git push --force backup main --tags`(备份库完全等于本地 main);
- **推完必须真核**:`git fetch backup && git rev-list --count backup/main..main` = **0**
  ——只信退出码不够,"以为推上去了"和"真推上去了"长得一模一样。
- **节奏:一段工作收尾就推,别攒着**(收尾命令 /wrap 的最后一步就是它)。
- **备份说明住主仓**:建 remote 那天在主仓写 `备份/README.md`(装得下/装不下清单+恢复步骤)——
  它描述的是机制、是活文档,跟主仓走,不放备份库里。
- **remote 建不成(owner 未提供/未同意)**:挂"要 owner 亲手做的:建备份库"(handoff §三)+
  主文档标警示"建立之前仓库只有本地一份,谨慎操作";建好当天补首推+核 0。

**装得下/装不下(写进备份 README)**:

- ✅ 装得下:全部代码、文档、提交历史(git 库本身就是完整备份)。
- ❌ 装不下、必须 owner 另存(列成清单):全部密钥(本来就不在仓库)/
  **推备份那把 SSH 私钥本身(最容易漏:它丢了就再也推不了,已推上去的不受影响,网页换新的十分钟)/
  服务器与云账号钥匙 / 大块可重建物(node_modules、venv——靠脚本重建)/ 还没 commit 的改动**。

## 三、恢复演练(建库第一周做一次,之后每季度)

1. 干净环境 clone 备份库 → 装依赖 → **跑一遍测试**(证明可恢复且可用);
2. 密钥按《密钥总备份》放回去 → 程序能起;
3. 恢复"继续推备份"的能力(装私钥/配 remote);
4. 云账号是服务器最高钥匙——"最该保管好的是云账号,其次才是钥匙文件"写进 README。

## 四、节奏表

| 时点 | 动作 |
|---|---|
| 第 0 天 | gitignore 密钥位 / 备份 remote / 首推 / 密钥总备份建档 |
| 每段收尾 | /wrap 最后一步:推备份 + 核 count=0 |
| 密钥增换 | 当天更新《密钥总备份》并提醒 owner 另存 |
| 每季度 | 恢复演练 + 核对"装不下"清单(新增的密钥/服务器补进去) |
