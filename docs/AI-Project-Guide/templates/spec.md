# spec ——【产品名】产品规格(做什么)

> 把 `demand.txt`(唯一权威需求源)细化成开发依据的**产品规格**。
> **只描述"做什么",不描述"怎么做"**(技术见 architecture.md,流程见 workflow.md,进展见 handoff.md)。
> 本文件是"产品当前应有的样子"的**现状快照**:改了用户可见行为,回来同步对应节。
> 功能后标注落地它的 SPEC 号(如 `(SPEC-003)`),从规格到需求可回溯。

## 1. 一句话定位

【给谁用的、解决什么问题的、一句话】

## 2. 目标用户

| 维度 | 设定 |
|---|---|
| 谁 | 【】 |
| 场景 | 【在家/在公司/…】 |
| 设备与环境 | 【】 |
| **不覆盖** | 【V2 再说 / 明确不做的人群】 |

## 3. 使用流程(站在使用者视角,像说明书一样从头走一遍)

> ⚠️ 这一节是本文件的灵魂:**用户在什么场景 → 做什么操作 → 看到什么/发生什么**。
> 逐段写,不列功能罗列;它就是验收时对照的剧本。

1. **第一次打开**:【用户看到的第一个画面是什么、从哪开始】
2. **核心流程**:【用户完成产品主打任务的全过程,一步一步】
3. **常用操作**:【保存/分享/设置/退出……】
4. **出错时**:【网络断了/输入错了/权限不够,用户看到什么】
