# 💸 债 —— 还欠 **N 笔**,其中 **M 笔**会随下一次发版一起消掉

> # ⇒ 要清零的是这两个数的差:**N − M = G 笔**(三数照抄进汇报第一句,别心算)

> 🔴 这 N 笔全是 agent 欠的债。分栏答"这笔债卡在哪",**不是"归谁"**。
> "观察"不是免做牌;唯一免做牌 = owner 亲口"等我发话"(写成"等 owner 发话",不是"不做"——
> 方向不一样:后者像被否了,而它一直在盘上、球在他那)。

## 卡在哪(先看这里,别往下翻)

| 卡在哪 | 几笔 | 怎么销 |
|---|---:|---|
| 不卡任何人 —— 现在就能动手(**下一件从这里挑**) | | 我做完 |
| `观察@年-月-日`(到点回来重判) | | 到点重判——"先不动"是我自己写的判断,不是免做牌 |
| **⇒ 小计:发版帮不上、只能我一件件做掉的** | | **🔴 要清零的就是它** |
| 代码写完,卡在发版 | | 发出去**且到用户手上**才算还清 |
| 等 owner 发话 | | 他说做的那天才动 |
| **总计** | | |

## 明细(每笔必填出处和去处)

| # | 做什么(一句话) | 出处(台账/lessons/对话) | 去处(下一动作·归谁·什么时候) |
|---|---|---|---|
| | | | 🚫 没有去处的条目不许存在 |

## 维护规矩(跟 git add 一个性质,漏了这段活等于没发生)

开一件:记一条+当场写去处 / 改一件:**只改那一行的去处**(别在第二处再写状态——
复述件必漂,且单向漂)/ 结一件:按出口销(修好上线·判定不做写清凭什么·转需求·并进别条·观察期满)。
**交接页里永远不出现"还剩几件"。** 本表只转述"去处"写的什么,不核那句话还成不成立——
那层只能靠"结一件当场销"守住。
