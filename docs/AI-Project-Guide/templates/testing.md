# testing —— 测试规范:怎么自证"做对了"

> 测试用例**从 SPEC 的 V 验证标准逐条转化**(断言 = V 原文),不是写代码时现想的。
> SPEC 里没有 V → 回 SPEC 补,别硬编用例。

## 0. 自测三层(顺序:跑通 → 自动化 → 看画面)

| 层 | 干什么 | 判据 |
|---|---|---|
| 1 冒烟 | 自己把功能真跑起来用一遍 | 主路径通;**给 owner 验收前备好双击就能跑的启动物** |
| 2 测试用例 | V → 自动化用例(单测/组件/E2E) | R↔V↔用例对得上;断言=V 原文;"成功态跟没发生长得一样"的功能要造出那个时刻并断言它发生了 |
| 3 可视化验证 | 界面/行为改动 → 截图/录屏**自己打开看过** | 🚫 没看过的图不许凭它说"验证过"——机器证明"图存在",证明不了"画面对" |

## 1. 什么时候跑什么(挂动作,不挂时钟;🔴 本表是唯一真值,别处只挂指针)

| 什么时候 | 跑什么 | 实测耗时 | 谁说了算 |
|---|---|---|---|
| 动完代码 | 静态闸:【typecheck/lint】 | 【秒级】 | 自己拍,照跑 |
| 要 commit | 只跑跟这次改动直接相关的一小份 | 秒~1分 | 自己拍 |
| 改了用户看得见的 | 一张截图自己看过再 commit | 分钟内 | 自己拍 |
| 全量 / 整套 E2E | —— | 【】 | 🔴 owner 批,一次一议;节奏=修完一批→申请一次 |
| 发版 | 发版闸:【清单】红一道不许打 | 【】 | 发版本就要他点头,闸是那次点头的一部分 |

> **耗时必须实测填**;没跑过的写【待实测,首跑后回填】,不许估个数充数——
> 这张表的价值就在"哪个档多贵"是量出来的,不是感觉出来的。

## 2. 挂了怎么找根因(速查)

先分类(产品坏了 vs 装置不真实)→ **复现不出=没理解,不动代码** → 改一行好了≠根因对
(改前稳定出现、改后稳定消失,两组都稳才算)→ 别人报的 bug:现象真,结论未必,
先翻自己的 V/判据再拿数据数。事件数不到两位数 → 查机理别做统计。

## 3. 守卫纪律

- 复述代码事实的地方配会红的静态断言;**期望值独立写死**(从被守对象取 = 假守卫);
- 新守卫**坏件回跑**一次:改回出事前的样子,它必须红,且红的是它;
- 永久红 = 没有闸(下一个人只会 skip),别立达不到的标准。

## 4. 发版闸(第一次打包前填)

每道闸只答一个问题。加闸前两问:① **拿上一次事故回测,它会不会红?**(不会=仪式,别加)
② 它看的东西跟用户屏幕上的**隔着几层**?(自己造输入→自己写断言=隔三层,只核对自己的世界观)

| 闸 | 答什么 | 命令 | 红=不许 |
|---|---|---|---|
| 【例:已知债务清零】 | 【】 | 【】 | 打包 |
| 【例:真跑一趟+人眼看图】 | 【】 | 【】 | 上架 |

灰度→正式之间:上架当天建**转正式总表**(owner 实测/等下包改动/正式版配套/剩余验收/转正当天动作
——五类天生散在五处),转正前整张过完,发完归档。
