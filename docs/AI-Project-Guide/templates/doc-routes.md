# doc-routes —— 文档路由表:「干这件事的那一刻,该看哪一节」

> **这份表不需要任何人记得去读它**:有钩子基础设施时,由钩子在动作发生那一刻查表,
> 把命中那行的话送到 agent 眼前;没有钩子时,它退化为 AGENTS.md 路由表的扩容页
> (触发词必须写成 agent 会怎么开口问的原话)。
> **加一条规矩 = 往表里加一行数据,机制一个字不改。**

## 种子行(按项目改)

| 什么动作 | 送到眼前的话 | 出处 |
|---|---|---|
| `secrets*` / `*.env` / `*key*` | 🚫 **停。密钥内容一个字符都不许流向输出**(含"看看键名")。程序自取走环境变量;不知道键名问 owner | AGENTS.md §红线 |
| `specs/SPEC-*.md` | 你在写需求文档。🔴 先讨论后落笔(值不值/选择题/界面确认);R 使用者视角 + V 可判定;Ready 前出测试覆盖矩阵 | workflow.md §〇 |
| `docs/handoff.md` | 交接页只装"发生了什么、为什么",**不装待办**;别为加一条删一条,该回收整批蒸馏进 history | doc-maintenance §交接页 |
| `$ git commit` | 🔴 **带 pathspec**(`git commit -m "…" -- <文件>`);提交前核 `git diff --cached --name-only` | lessons §L## |
| `$ <全量测试命令>` | 你要跑全量。🔴 必须先经 owner 批,一次一议;提交前只跑相关一小份 | testing.md |
| `? (为什么|怎么回事|根因|排查)` | 你要找根因——先戴科学家帽:**先别给方案**;对照实验设计先给 owner 审;他报的 = 一个观察点不是全部 | lessons/diagnosis 相关节 |
| `? (值不值|要不要做|划不划算)` | 两栏(好处用数/代价含"可能碰坏什么")→ 三出口。最省钱一问:**这条规则真实数据里被触发过几次?数一遍比实验便宜三个量级** | AGENTS.md §边际效益 |
| `? (汇报|报告一下|说一下进展)` | 动笔前打开 how-to-report **照着填**,别凭记忆写:标题=他会问的问题;一条消息一件事;收尾是行动表 | how-to-report.md |
| 【项目自填:高频改动的文件】 | 【它自带的规矩一句】 | 【精确到节】 |

## 加行规矩

- 三列:动作(路径通配 / `$` 命令 / `?` owner 的话)· 一句大白话(≤3 行)· 出处**精确到节**。
- 前缀:(无)= 提醒一次 / **⏳** = 提醒 + 提交时再核一次账(规矩当场做不完的) /
  **🚫** = 每次都拦(只给安全红线)。
- 表自守卫:出处还在吗(文档改结构会红)+ 规则还匹配得到文件吗(代码改名会静默失效)。
  **加完一行,自己真触发一次**——守卫验不出"漏了一部分"。
- `?` 类门槛最高:只匹配意图非常明确的词,拿不准别加(它挂在每一轮对话上,误报烦的是 owner)。
