# 05 · 交接与收尾 —— handoff / lessons / history 的关系,/wrap 命令

> **答两个问题**:① handoff、lessons、history 三者各装什么、内容怎么流动;
> ② /wrap 收尾命令怎么建立、怎么用。

---

## 一、三份文档的关系(一张图 + 一张表)

```
        写入(干活时)                    搬运(收口时)                 终点
handoff ── 上一段发生了什么、为什么 ──┐
                                    ├─ 发一版/页面翻不动了 ──→ history/progress/(时间轴)
lessons ── 踩过的坑(症状+根因+修法) ─┤                          history/standalone/(快照轴)
                                    └─ 高频坑 → lessons-quickref(指针层,正文不动)
debt/changelog 等 ── 条目完结 ────────────────────────────────→ 对应归档轴
```

| | handoff(交接页) | lessons(坑账) | history(归档区) |
|---|---|---|---|
| 装什么 | 现在进行时:现在在哪、上一段为什么这么改 | 经验:哪些路别再走(**只增不删**) | 过去时:当时做了啥、结果如何(**冻结只查**) |
| 时态 | 现在/最近 | 跨时间 | 过去 |
| 怎么长 | 干完活往上加一条 | 踩坑当天加一条 | 只进不改(修断链除外) |
| 怎么短 | **整批蒸馏**进 history/progress | 不变短,靠 quickref 分流查阅 | 不变短(靠 INDEX 压缩查阅成本) |
| 判据 | 这句是"为什么"叙事? | 这句是"以后别再踩"? | 这段已完结、不再需要维护? |

**搬运规矩**:

- **handoff 整批回收,绝不逐行削**:平时该加就加别管行数;发一版(或翻不动了,目测 300 行+)
  把这批已完结的**整批**蒸馏进 `history/progress/`(每份:时间·主题·一句话结果·Grep 关键词,
  并在 `history/INDEX.md` 登记)。🚫 **不设行数硬顶、绝不为加一条删一条**——硬顶逼人删
  "最好删的"而不是"最不值钱的"。**归档和登记是两个动作**,做了前一个别忘后一个。
- **lessons 的分流**:高频坑(被坑 ≥2 次或一次代价大)进 quickref,**quickref 只放指针**
  (`症状→一句话因→看 L##`),正文永远在 lessons;**每加一条,同一次提交挪走一条**
  (上限绑在动作上才有效,写数字上限必失效)。
- **history 三轴**:时间轴 `progress/`(交接页蒸馏)/ 版本轴 `releases/`(changelog 归档、
  发版快照)/ 快照轴 `standalone/`+`code-reviews/`(定点评估、被取代的旧方案)。
  **落不进三轴 = 它可能不是历史**,回活文档区想清楚。
- **该停用的文档**:挂停用横幅 + 索引行同步标停 + 指明替代品在哪——
  停用文档冒充现状,比没有文档更坑。

## 二、/wrap:收尾命令

### 为什么必须有它

上下文压缩(compact)会把没落盘的东西全部烧掉。源项目的实测教训:压缩后 agent
读到的第一条指令是"把清单做完",而清单里全是边角料,**owner 真正等的事不在里面**。
⇒ **要保的东西必须在盘上,不在指令里。**

一条判据定义整个命令:**做完所有需要上下文的判断,不做任何不需要上下文的执行。**
判断("当初为什么这么改")只有这段对话答得出;执行(修 bug、改正文)压缩后照样能做。

### 怎么建立(两种平台)

`/wrap` 就是一个 markdown 文件,放进命令目录即成斜杠命令:

| 平台 | 放哪 |
|---|---|
| Claude Code | `.claude/commands/wrap.md` |
| ZCode | `.zcode/commands/wrap.md` |
| 两边都用 | 主文件放一处,另一处放一行薄指针("真源:../../.claude/commands/wrap.md") |

- [ ] 复制 [`templates/wrap.md`](./templates/wrap.md) 到上述位置(⚠️ 命令目录里的文件
  **下个会话才出现在斜杠菜单里**,不是即插即用);
- [ ] 同时建 `docs/warp-todo.md`(或 wrap-todo.md):一轮寿命的执行清单,头部写死规矩
  ("只放执行不放判断;压缩后第一个动作=做完并清空;不许过夜,过夜必给去处")。

### 怎么用(owner 敲 /compact 前,或你判断上下文将满时)

六步(全文住模板,这里给骨架+判据):

1. **判时机**:后台任务没回来/半截代码没验/对照实验中途/欠 owner 一个要靠这段上下文才答得出的
   答复——命中任何一条说"先别压"。
2. **快速自检**:工作树、还在跑的进程(活过压缩的进程会被下个上下文再起一个,互相撞)、清单纯不纯。
3. **把只活在对话里的东西写下来**(永远排在扫文档之前——**不可恢复的动作排在可恢复的前面**):
   量出来的数(连怎么量的)/ owner 拍的板+理由(落进它们该住的正文,不是交接页)/
   干到一半的"下一步从哪接" / 答应他的事和等他定的问题(**没有任何东西会提醒这类**)/
   临时产物的处置(判据:新 agent 照这条能不能重建它)。
4. **扫文档同步表**:逐行给判定(要改/不涉及),**判定当场做完,动手留给清单**;
   交付时列得出扫过的清单——"都同步了"这句话本身不是证据。
5. **落盘**:核测试记录("引用上一趟"和"跑了测试"分开说)、断链扫描、commit(带 pathspec)、
   推备份、核 count=0。
6. **报告**:三数句式 + 能不能压 + 存了什么改了啥(带提交号)+ 清单几条逐条点名
   (空项明说"没有了"——空项和忘了写长得一模一样)。

**压缩之后两步**(防注意力被清单钉死):① 清单做完清空 →
② **回交接页接主线**(指路用名字不用位置)。
