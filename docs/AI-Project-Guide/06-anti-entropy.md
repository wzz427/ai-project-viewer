# 06 · 防熵增要则 —— 文档开始烂了,翻这一页

> **定义:熵增不是"文档变多"(多是资产),是"信息失效而没人知道"。**
> 全部要则围绕一个判据:**一个事实过期的那一刻,有没有任何东西变红?**

## 五条要则

1. **单一真值 + 指针**:一个事实只住一个地方,别处只放指针。
   抄了必漂,漂了没人会红,而且单向漂(没人把"已修"改回"未修")。
   消不掉的复述(承诺跟现状一致的清单)→ 配一道**会红的守卫**对拍;
   期望值独立写死,写完**坏件回跑**一次(改回出事前的样子,它必须红)。
2. **状态只住一处,每笔带去处**:一件事的状态只在源账那行的"去处"字段;
   没有去处的"待办"不许存在(列出来了没人做、没人发现没人做 = 埋坑)。
   账必须有**出口**(修好/不做·写清凭什么/转需求/并进别条/观察期满),光进不出 = 黑洞。
3. **膨胀靠整批回收,绝不逐行削**:交接页翻不动了 → 整批蒸馏进 history;
   🚫 不设行数硬顶、不为加一条删一条(硬顶逼人删最好删的,不是最不值钱的)。
   上限要绑在动作上("每加一条挪走一条"),写数字上限必失效。
4. **引用用名字,不用章节号;索引抬头 = 别人会问的那句话**:重排一次主文档,
   全仓按章节号写的引用全变死号、没有任何东西红过(源项目实测 290 处/140 个文件)。
   索引里"版本管理规范解析"这种抬头没人搜得到,"查这版改了啥"才行。
5. **改口留痕 + 停用挂横幅**:推翻旧结论 → grep 旧那句**逐处改掉**,原地留
   "某月某日改口,出处 X";文档停用 → 横幅 + 索引同步标停 + 指明替代品。

## 配套动作

- **入口改版 → 路由回归**:改了 AGENTS.md/索引之后,装作只带它的新 agent,
  拿标准任务单("现在进展是什么/撞了个报错去哪/这版改了啥/历史决策为什么")走
  "第一跳去哪、几跳到位"——**断链扫描只护"链接指得到",护不了"意图找得到"**。
  删一句话之前问:它是不是某文档唯一的读入口?
- **终极节流是少记**:能当场做掉的别写成条目;能不立的规矩别立(每条规矩都是未来的负债);
  能让机器算的别让人抄。**记账是成本,不是产出。**

## 症状速查

| 症状 | 用哪条 |
|---|---|
| 两处写着同一事实,已经对不上 | 要则 1 |
| 待办挂着没人接、没人发现 | 要则 2 |
| 交接页/账本翻不动 | 要则 3 |
| 重排后旧引用全断、没人发现 | 要则 4 + 路由回归 |
| 旧结论已推翻,别处还引旧话 | 要则 5 |
| 规矩写对了但没人执行 | 到点送达的路由表(见 [`04-doc-operations.md`](./04-doc-operations.md) §三) |
