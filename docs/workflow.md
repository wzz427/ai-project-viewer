# workflow —— 需求驱动开发流程(状态机 + 三步曲 + 跃迁自检)

> 本项目一切开发围绕 SPEC 状态机流转。**每个跃迁前必须过明文自检,不过不许跃迁。**
> 建自:2026-10-01,照 docs/AI-Project-Guide/templates/workflow.md 落地,本项目适配见 §五。
> 台账:specs/INDEX.md(状态与去处的唯一真值);SPEC 模板:specs/SPEC-template.md。

## 〇、需求文档(SPEC)的写法(动笔前必读)

- **编号**:需求条目 R1、R2…;验证标准 V1、V2…(分开编号、互相引用)。
- **R 站在使用者视角**:用户在什么场景 → 做什么操作 → 看到什么/发生什么。**不写实现。**
- **V 可判定**:每条 R 至少一条 V,"什么样算对"写得能直接变测试用例。
  ✓ "输入空名字点创建,弹窗不关、名字框变红、提示'名称不能为空'"
  ✗ "有合理的输入校验"(没法验)。人工项标 V-human,原则上 ≤ 自动项一半。
- **穷尽性**:"看似一个按钮"的 SPEC 大概率漏(空态/加载/错误/重名/快捷键/撤销/持久化…);
  不适用的维度显式标 N/A+一行理由,不许默默跳过。
- **无游离 R**(没 V 的规则不许存在);测试覆盖矩阵 = Draft→Ready 的硬产物。
- **作废不删,重标注**;依据记进"决策依据"节(结论+理由+排除了什么+为什么),
  **同一条依据写进它管的那段代码的头注释**。

## 一、三步曲(每个需求都走,顺序不许乱)

### (a) 讨论 —— 思路 + 技术方案;界面先行
写 SPEC 之前先过讨论:**值不值得做**(两栏三出口)→ **核心选择题 3-5 个** → **有标杆必对照** →
**涉及界面的,先出界面方案**。本项目里"讨论"的对象是 owner;**动笔前有疑问/要变化,先跟 owner 确认**
(2026-10-01 owner 原话立规,见 §五)。

### (b) 落笔 —— 技术实现方案写进 SPEC,再开发
讨论结论 → SPEC 正文(R+V)+ 技术实现方案(模块拆分/动哪些文件/关键取舍/决策依据)→ 开发。
开发中 R 变了 → 回 SPEC 改,**别只改代码**。

### (c) 交付 —— 自测 → 测试用例 → 可视化验证 → 交 owner
① 自己跑通主路径,备好**双击就能跑**的启动物(桌面快捷方式);② V 逐条转测试用例;
③ 界面/行为改动**截图自己看过**(方法:docs/testing.md §1 GUI 基建);④ 按 docs/how-to-report.md 汇报,
owner 验收原话记进 SPEC,状态改 Done。

## 二、状态机与跃迁自检

```
Pre-Draft(对话) → Draft → Ready → InDev → InTest → Done →(冷却)→ specs/archive/
```

| 跃迁 | 自检门(不过不许跃) |
|---|---|
| → Draft | 三步曲 (a) 走完:值不值已判、选择题已拍、界面已有确认基线(§五) |
| Draft → Ready | 测试覆盖矩阵已出;穷尽性清单过完;~~方案 owner 拍过~~(2026-10-01 owner 免审,改为:**agent 自核 R/V 与 V1.5 逐条对上 + 决策表齐 + 疑问已确认**,§五) |
| Ready → InDev | 依赖基建已就位;环境能跑;~~界面线框已获 owner 确认~~(2026-10-01 适配:**V1.5 已含界面明文的视为已确认;未含的决策表代取默认+标"未确认"**,§五) |
| InDev → InTest | 三步曲 (c) 的 ①②③ 全做;相关测试档全绿(testing.md 档位) |
| InTest → Done | **owner 验收原话**落进 SPEC;遗留项已记账(带去处)——**此门不可代拍** |

## 三、台账与归档

- `specs/INDEX.md` 唯一台账:编号|标题|状态|**去处**。状态一变 → 同步 INDEX;它同时是债务表的源账。
- Done 冷却后整体搬 `specs/archive/`,INDEX 留一行索引。
- **基建类需求(SPEC-INFRA-NNN)与业务需求平级**:验证手段被反复需要(GUI 自动化基建、
  回放器、夹具、基准)→ 单独立项,别在每个业务 SPEC 里现造。

## 四、owner 不在场时(代拍规矩)

红线只有一条:**不许编造"owner 已同意"**。① 只有需求原话/已有决策明文预授权的才可代取默认;
② 代取的一切在 SPEC 明标"代取默认/未确认",问题清单挂 handoff 挂账区;③ 跃迁照走,记录写明
代拍依据+**回退条件**;④ 不可代拍的硬门:InTest→Done(owner 验收原话)、对外发布;
⑤ owner 回场逐条复核挂账区,结论当天写回对应 SPEC/决策表。
