# how-to-report —— 给 owner 的交付汇报怎么写

> 动笔写汇报前打开这一页照着填。判据:owner 不看代码、不翻文档,
> 只读汇报就能**拍板**(验收/打回/追问)。

## 结构(缺一不可,顺序固定)

1. **一句话结论**——交付了什么、状态是什么(等验收/有阻塞)。
2. **验收对照表**——本期规格条目 → 实测结果 → 证据(数字/截图/命令输出)。
   规格条目用 owner 语言(“重复添加同一项目会切换到已有标签页”),不用内部编号。
3. **Benchmark/关键数字**——有就上表,给目标值和实测值两列。
4. **已知问题与技术债**——每条带“去处”(哪个 Phase/哪个账本收),不许裸奔。
5. **下一步**——明确说“等你点头后进 Phase N”,列出需要 owner 决定的事(若有)。

## 写法规矩

- 中文、说人话、无内部代号(SPEC 编号不出现;Phase N 可以出现,owner 熟悉)。
- 数字必须来自实测,注明口径(哪台机器/哪个构建/几轮);没测的写“未测”,不编。
- “全部通过”必须有对照表背书;有任何一条没验,单独点名,不藏在“基本完成”里。
- 问题不粉饰:超标的指标直接写超标和判读,给 owner 决策依据而不是替他决定。
- 汇报后必须停止(V1.5 §191),下一步等 owner 明确说进下一 Phase。

## 时机

每个 Phase 交付时、每次需要 owner 拍板时。汇报本体发在会话里;
关键数字同步落 testing.md / handoff.md(汇报是快照,账本是真相)。
