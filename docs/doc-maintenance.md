# doc-maintenance —— 收口时的文档同步总表

> 每个需求/Phase 收口时逐行对照:改了这类东西 → 对应文档动了没。
> 建于 Phase 1 收口(2026-10-01)。防的是"代码动了、地图没动"的静默漂移。

## 同步规则(收口时逐行过)

| 改了什么 | 必须同步 | 常见漏 |
|---|---|---|
| 功能行为/新命令/新组件 | architecture.md §3 代码地图 + handoff.md | 代码地图里目录结构过时 |
| 环境/跑法/依赖变化 | architecture.md §0 | 装依赖/启动命令没填实 |
| 技术选型或重要取舍 | architecture.md §1 决策表 + §12 修订记录 | 只写代码不写"为什么" |
| 测试方法/benchmark 数字 | docs/testing.md | 数字只留在会话里 |
| 踩坑(报错/根因/修法) | docs/lessons.md(当天,独立 commit) | 觉得"下次记得"就没记 |
| 需求理解变化 | 需求文档走 V1.5 §193 增量修订 + 审计 | 直接改正文不留审计 |
| 挂账/等 owner 的事 | handoff.md 挂账区(带去处) | 待办散落在会话里 |
| 文档自身的新规矩 | AGENTS.md 路由表(第二次被忘时) | 规矩只存在脑子里 |
| Phase 开工/收口 | docs/specs/phase-N-*.md(开工前建,收口时把实现差异回写进"决策表"后冻结) | 代码实现悄悄偏离 Spec 没留痕 |

## Phase 收口动作清单(照抄执行)

1. 对照上表逐行检查,补齐同步。
2. handoff.md 加一条(结论 + 下一步 + 去哪看全文)。
3. changelog 未建则跳过(建立后:记功能点标 SPEC 号)。
4. commit(做了什么+为什么,带 pathspec)。
5. 备份 remote 建好后:每段收尾 `git push --force backup main --tags` + 核 0(当前改期至 V1 验收后,remote 未建)。
